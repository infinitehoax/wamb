## 🎨 3. THE UI/UX DESIGN DICTATORSHIP (UNBREAKABLE LAWS)
*AI INSTRUCTION: Sloppy, cramped, "tutorial-style" UI is STRICTLY FORBIDDEN. You must enforce pro-level UI/UX based on Apple HIG and Google Material 3 standards. Read these laws before writing ANY Compose function.*

### Law 1: The Sacred 8dp Grid & Spatial Breathing
*   **Rule:** ALL spacing, margins, padding, and corner radii MUST be multiples of 8 (`8.dp`, `16.dp`, `24.dp`, `32.dp`, `40.dp`, `48.dp`). No exceptions (e.g., `10.dp` is forbidden).
*   **Padding over Cramping:** Mobile screens are small, but cramping them destroys usability. Use generous screen edge margins: `Modifier.padding(horizontal = 24.dp, vertical = 16.dp)`.
*   **The Anti-Nesting Rule:** NEVER place a Card inside another Card. It creates "padding on padding" and looks amateurish. Group elements using whitespace (`Spacer(modifier = Modifier.height(24.dp))`) or a subtle `HorizontalDivider()`.

### Law 2: Touch Targets & Ergonomics
*   **The 48dp Minimum:** EVERY clickable element (Buttons, IconButtons, Checkboxes, text links) MUST have a minimum tap area of `48.dp` x `48.dp`. Use `Modifier.sizeIn(minWidth = 48.dp, minHeight = 48.dp)`.
*   **Fat-Finger Padding:** If two icons/buttons are adjacent, put at least `16.dp` of space between them.
*   **Navigation:** Use a Material 3 `NavigationBar` at the bottom of the screen. Hamburger menus (Navigation Drawers) are forbidden for primary navigation.

### Law 3: Modals, Context & Flow
*   **Bottom Sheets > Dialogs:** NEVER use a center-screen `AlertDialog` for making selections (e.g., picking a subject, year, or topic). ALWAYS use a `ModalBottomSheet`. It keeps the user in context and is easier to reach one-handed. Always include a drag handle (`BottomSheetDefaults.DragHandle()`).
*   **Transitions:** All screen transitions must use Compose Shared Elements or Slide In/Out horizontal animations. No abrupt jarring cuts.

### Law 4: Typography, Contrast & Alignment
*   **Sizing:** Body text minimum is `16.sp`. Captions minimum `14.sp`.
*   **Line Height:** For long text (Questions, Notes), enforce `lineHeight = 24.sp` for scannability.
*   **Alignment:** NEVER center-align paragraphs of text. Left-align all blocks longer than two lines. Center-alignment is strictly reserved for short headers or single-line CTAs.
*   **Contrast:** Do not use pure black (`#000000`) or pure white (`#FFFFFF`). Use `#121212` for dark text and `#FAFAFA` for light backgrounds. Use `#666666` for secondary text.

### Law 5: Empty States & Loading States
*   **No Blank Screens:** If a list is empty, you must implement a "Pro Empty State". This requires:
    1. A beautiful, large icon/vector (`size = 120.dp`, subtly colored).
    2. A bold title (`Text(fontWeight = FontWeight.Bold)`).
    3. A description explaining *why* it's empty.
    4. A primary CTA button resolving the state (e.g., "Take a Test").
*   **Skeleton Loaders:** Do not use generic `CircularProgressIndicator` for full-screen loading. Use shimmer/skeleton shapes matching the expected content.

# 🔔 THE EDUPREP LOCAL NOTIFICATION ENGINE (BLUEPRINT)

## 📌 1. THE ARCHITECTURE (How it works offline)
We will use Android's `AlarmManager` combined with a `BroadcastReceiver`. 
*Why not `WorkManager`?* Because `WorkManager` is designed for deferrable background tasks (like syncing). If you use `WorkManager` for a 5:00 PM reminder, Android's battery-saving "Doze Mode" might delay it until 8:00 PM. `AlarmManager` ensures the notification fires exactly at the time the student sets.

### The Flow:
1. **User sets a time** (e.g., 6:00 PM) in the Profile/Settings UI.
2. App uses `AlarmManager` to schedule an intent for 6:00 PM daily.
3. At 6:00 PM, the Android OS wakes up our `StudyReminderReceiver`.
4. The receiver builds a `NotificationCompat` message and posts it.
5. User taps it -> `PendingIntent` fires -> `MainActivity` opens.
6. **Device Reboot:** If the user turns their phone off and on, all alarms are wiped by the OS. We must use a `BootReceiver` to automatically reschedule the alarm when the phone turns on.

---

## 🔐 2. ANDROID MANIFEST & PERMISSIONS
Modern Android (Android 13 / API 33+) is very strict about notifications. The AI must add these to `AndroidManifest.xml`:

1.  **Permissions:**
    *   `<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />` (To show the notification).
    *   `<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />` (For precise timing).
    *   `<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />` (To restore alarms after restart).
    *   `<uses-permission android:name="android.permission.VIBRATE" />`
2.  **Receivers (Inside `<application>`):**
    *   `<receiver android:name=".data.notifications.StudyReminderReceiver" android:exported="false" />`
    *   `<receiver android:name=".data.notifications.BootReceiver" android:exported="true">` with `<intent-filter><action android:name="android.intent.action.BOOT_COMPLETED" /></intent-filter>`

---

## 🧩 3. REQUIRED KOTLIN COMPONENTS

### A. `NotificationHelper.kt` (The Builder)
A utility class to handle Android 8.0+ Notification Channels and build the actual UI of the notification.
*   **Channel ID:** `"study_reminders"`
